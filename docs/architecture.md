# Architecture

Where the code lives. What each piece does is in its own docblock or header comment, never here (`AGENTS.md#doc-rules`). The rules the code follows are [principles.md](principles.md).

## Tech stack `#tech-stack`

- Godot 4 **.NET edition**, C#. Forward+ renderer, Jolt physics, physics interpolation on.
- A 3D world seen by a locked side camera: a narrow-FOV perspective camera (not orthographic), so the depth layers move at different speeds.
- Play happens on the Z = 0 plane: the pilgrim and every gameplay body stay on it, and all gameplay physics is on X/Y.
- Versions and install paths: [toolchain.md](toolchain.md). Working with Godot files as text: [godot-csharp.md](godot-csharp.md).

## Layout `#layout`

The three layers (core, adapters, content) are `docs/principles.md#engine-detail`. On disk:

```
project.godot          input map, physics layer names, shader globals, settings
TheDeep.csproj, .sln   the game (generated by Godot; references the core, excludes core/ and tests/)
AGENTS.md, CLAUDE.md   the agents' entry point (CLAUDE.md is "@AGENTS.md")
.claude/settings.json  the agents' project settings (auto memory off: AGENTS.md#no-memory)
docs/                  every other doc (ignored by Godot)
core/                  the core: TheDeep.Core.csproj, no Godot reference. Its folders are named after the adapters'
                       they serve (core/map/ for scripts/map/), namespace TheDeep
scripts/               the adapters: Godot nodes and resources, one folder per system
scenes/                shared scenes: the main scene, the player, the room stage, props, the kit block, camera, fx, UI
worlds/<name>/         one world's content: world.tres (its WorldDefinition), its network, its line book, rooms/
resources/             the live tuning, biomes, part assemblies, machine species
assets/                shaders (shared code in shaders/lib/), materials, particle materials
tests/TheDeep.Tests/   xUnit over the core
tools/                 the check, look-dev captures, the map report, authoring helpers
```

## Where systems start `#entry-points`

The type to open first for each system; its docblock leads on.

| System | Start at |
|---|---|
| Boot, command-line arguments | `Main` |
| The pilgrim | `Player` (over the core's `PilgrimControl` and `MoveRules`), its states in `scripts/player/states/`, its look `PlayerVisual` |
| A world, its rooms and travel | `WorldDefinition`, `World`, `Room`, `RoomExit`, `RoomTravel`, `RoomStage` |
| The run and the save | `Session` (over `Pilgrimage`), `SaveFile` |
| Items (keys, codes) and locked doors | `ItemDefinition`, `Keyring` (over `Inventory`); in the requirement language, `Requirement` |
| Power-ups | `PowerUp`, `PowerUps` (over `Prowess`) |
| Machines | `Machine`, `MachineSpecies`, `MachineDirector`; brains in `core/machines/brains/` |
| The map and its proof | `MapGraph`, `MapSolver`, `ReachPlanner`, `MapDraft`, `WorldCheck`; fed by `RoomValidator` |
| Looks | `BiomeProfile`, the painted signature `PaintPass` (its compute shaders in `assets/shaders/paint/`), the kit (`KitMesh`, `KitShapes`), the part system (`PartAssembly`, `PartBody`), `assets/shaders/` |
| Text | `LineBook` |
| Captures | `OwnerCapture`, `LookDevDriver` |
| Checks | `scripts/debug/` (one driver per check, `docs/testing.md#check`) |
