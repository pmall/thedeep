## Formatters, linters and checkers <a id="format-tools"></a>

Each is the standard tool of its language, pinned to an exact version so every machine formats and lints alike (`AGENTS.md#checks`); the check runs them (`docs/testing.md#check`), and nothing is installed system-wide but uv: the project's toolchain stays .NET plus uv and Python (owner: no Node).

| Files | Formatter | Linter, checker | Version, pinned in | Installed by |
| -- | -- | -- | -- | -- |
| C# | `dotnet format`, by `.editorconfig` | the compiler with the SDK's `Recommended` analyzers and the code style of `.editorconfig`, on the game, the core and the tests (`Directory.Build.props`); the few rules turned off are in `.editorconfig`, each with its reason | the .NET SDK's | the SDK |
| Markdown | mdformat with its tables plugin, by `.mdformat.toml` |  | mdformat **0.7.22**, mdformat-tables **1.0.0** (its newest needs mdformat 0.7), `tools/check.sh` | `uvx`, which downloads each pinned version once into uv's cache |
| JSON (`.claude/settings.json`) | Python's `json.tool`, two-space indent |  | the system `python3` |  |
| Python (`tools/*.py`) | Ruff, by `ruff.toml` | Ruff; mypy, strict | Ruff **0.17.4**, mypy **2.4.1** (with Pillow **12.1.1** for its types), `tools/check.sh` | `uvx` |
| Shell (`tools/*.sh`) | shfmt **3.14.1** (`shfmt-py` 4.2.0), by `.editorconfig` | ShellCheck **0.11.0** (`shellcheck-py` 0.11.0.1) | `tools/check.sh` | `uvx` |

To upgrade one, change its pin (and the date `uvx` resolves dependencies at, beside the pins), run the fast check (it reformats), and commit the reformat on its own.

## What needs the GPU <a id="gpu"></a>

- **No GPU needed:** editing code and data, `dotnet build`, the unit tests, and the whole of `tools/check.sh` (every Godot step runs `--headless`), `tools/map.sh`. A laptop with the toolchain above (Godot .NET, the .NET SDK, ffmpeg) does all of it; the check is CPU-heavy (`docs/testing.md#check-fast`; longer on a laptop).
- **GPU needed:** `tools/capture.sh` (photo spots, motion reels, frame times) and the owner's F12/F10 captures render in a real window with Vulkan. Visual work is judged from these captures, and frame times only mean something on the RTX 3060, so visual items (stage bricks, the pilgrim's look) are done on the desktop. Running them while a game uses the same GPU spoils the frame times.
- So code-only items can go on a laptop, or on the desktop while it is busy with a game; visual items need the desktop's GPU to itself while capturing.

## .NET environment <a id="dotnet-env"></a>

- The shell profile does **not** put .NET on `PATH`.
  - `tools/check.sh` sets `DOTNET_ROOT` and `PATH` itself.
  - The `godot` wrapper sets `DOTNET_ROOT`.
  - In ad-hoc commands, use `~/.dotnet/dotnet`, or first export `DOTNET_ROOT=$HOME/.dotnet PATH=$HOME/.dotnet:$PATH`.
- Without `DOTNET_ROOT`, Godot looks in `/usr/share/dotnet`, fails to load .NET, and a windowed run can appear to hang.
- Every shell command runs in a fresh shell, so environment variables don't carry over between commands.

## Upgrading Godot <a id="upgrading-godot"></a>

`Godot.NET.Sdk` in `TheDeep.csproj` must stay at **exactly** the engine version. To upgrade:

1. Download the new **.NET** build from the official GitHub releases and verify it against `SHA512-SUMS.txt`.
2. Unzip it into `~/.local/opt/godot/`.
3. Point the wrapper at the new binary.
4. Update the SDK version in the `.csproj`.
5. Run `tools/check.sh`.
